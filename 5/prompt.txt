## 本轮总目标

让 FORGE 从已经具备 Super-agent 架构的工程，进化为真正能够长期自主工作的通用 Super-agent。

重点完善以下能力：

### 1. Router Intelligence

- 提升多 Workspace 意图识别和 Quest 关联准确率。
- 支持多个并行任务的持续协调。
- 优化事件批处理，减少不必要的模型调用。
- 支持任务优先级、阻塞判断和主动进度汇报。
- 支持对 Worker 结果进行判断、追问、重新委派和终止。
- 避免 Router 退化为纯任务登记器或简单转发器。

### 2. Worker Autonomy

- Worker 应具备真正独立的模型推理和工具调用循环。
- 完善复杂任务内部的子任务规划与依赖管理。
- 支持有界的专家协作和动态扩展。
- 完善错误分类、策略调整、有限重试和失败求助。
- 支持暂停、恢复、取消、崩溃恢复。
- 不允许通过无限增加 Token、输出长度或重试次数解决问题。

### 3. Adaptive Agent Swarm

重点提升动态组队质量，而不是固定启动六个角色。

支持：

- Single Worker
- Parallel Specialists
- Sequential Specialists
- Hierarchical Team
- Dynamic Expansion
- Model Replacement

Router 根据任务复杂度、能力需求、模型可靠性、工具兼容性、成本和延迟决定是否组队。

保留单 Agent 基线，并通过真实任务比较不同组队策略。不要预先宣称某种算法最优。

### 4. Model Intelligence

强化现有 Model Registry：

- 自动发现可用模型及其能力。
- 测量实际延迟、吞吐量和失败率。
- 统计真实任务成功率、工具成功率和 Reviewer 通过率。
- 建立数学、编程、研究、设计、视觉、规划等能力评测。
- 记录来源、样本量、测量时间和置信度。
- 支持任务级动态选模和模型故障切换。

优先使用已经授权的本地 Provider 和真实模型。

不得打印密钥，不得修改用户原有 Provider 配置，不得无限增加模型预算。

### 5. Workspace & Chain of Recall

- 增强跨项目自动识别。
- 多 Workspace 记忆隔离。
- 支持跨 Quest、Worker、Artifact 和历史决策检索。
- 优化多跳 Recall。
- 支持长期对话的上下文恢复。
- 保证压缩后原始证据仍然可以追溯。

用户始终只使用一个对话入口。

### 6. Watchdog & Self-Recovery

在现有 Watchdog 上继续完善：

- Worker 卡死识别。
- 任务长期无进展检测。
- Provider 故障检测。
- 执行环境异常检测。
- 过期租约恢复。
- 组件崩溃恢复。
- 未知外部副作用保护。

区分进程存活和任务实际进展。不能只根据心跳正常就认定任务正常。

不得重复执行结果未知的外部操作。

### 7. Tool Runtime

逐步扩展本地工具能力：

- Filesystem
- Python
- Git
- Terminal
- Browser
- MCP
- GPU diagnostics

优先保证 Worker 能真实完成编程、研究和文件操作。

保持原有 Policy、Approval、Evidence 机制。工具权限必须最小化，工作目录必须隔离。不要把普通工作目录隔离描述成 OS 安全沙箱。

## 开发策略

本轮允许连续开发，不必每完成一个小模块都等待我确认。

建议按以下顺序推进：

Sprint A：Router Intelligence 与多 Workspace 连续性。

Sprint B：Worker 自主规划、工具执行和自我修正。

Sprint C：Adaptive Swarm 与专家协作。

Sprint D：Model Intelligence 和真实模型评测。

Sprint E：Chain of Recall 与长期上下文恢复。

Sprint F：Watchdog 和故障自恢复。

Sprint G：真实复杂任务端到端验收。

每个 Sprint：

1. 先审查现有实现。
2. 找出实际缺口。
3. 编写针对性回归测试。
4. 实施最小必要改动。
5. 使用真实 Provider 验证关键能力。
6. 更新文档和状态。
7. 通过验收后继续下一 Sprint。

不要为了完成清单而重复建设已有模块。

## 真实任务验收

至少完成以下三个场景：

**L1：普通项目任务**

用户要求分析一个本地项目，找到问题并生成修复建议。Router 自动识别 Workspace，选择 Worker，读取真实文件并交付结果。

**L2：多专家研究**

用户要求调研一个 Agent 框架，分析架构、比较技术方案并生成报告。系统按需组建 Research、Architect、Reviewer 等角色，完成真实资料分析和审查。

**L3：自主开发任务**

用户要求开发一个具有明确验收标准的小型功能。系统自主规划、选择模型、编写代码、运行测试、根据失败修正，必要时动态增加专家，最终交付真实代码和测试证据。

至少一个场景必须验证：

- 两个独立 Workspace。
- 多个并行 Worker。
- Thread Subscription / Pass-through。
- Core 中途重启。
- Context Compaction。
- Chain of Recall。
- 最终结果回传原始 Router。

真实模型调用、Mock、程序化测试必须分别标记。

## 研究要求

对 Adaptive Team Composition、Task-Centric Context、Self-Recovery 建立可复现评测。

比较单 Agent、固定团队、动态团队和不同模型路由策略。

记录任务成功率、成本、延迟、Token、工具调用、返工次数、恢复成功率和证据完整率。

小样本结果只报告探索性结论，不夸大效果。
