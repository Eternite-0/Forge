# ADR-006：持久事件投递与任务图

日期：2026-11-15（Asia/Shanghai）。状态：已采用，Worker 执行仍属后续里程碑。

Quest 计划是有向无环图，节点、边、预算、版本及审批摘要持久化。用户审批绑定计划修订与内容摘要；暂停、恢复、取消和重试遵循状态校验和版本 CAS。计划生成只提出任务，不授予模型工具权限或证明 Worker 执行。

事件按消费者保存投递状态，claim 产生带截止时间和随机令牌的租约；过期令牌不能提交结果。handler 的数据库变更、Inbox 和确认在同一事务中完成；失败回滚后按有界退避重试，超过上限进入死信。消费者游标只跨过已处理的连续区间，优先事件不能使较早待投递事件被跳过。明确的重放需要记录操作者和原因；投递至少一次不意味着外部副作用恰好一次。

应用生命周期管理独立的 dispatcher 与 Router 处理循环，避免缓慢模型推理阻塞重要事件的入队。模型决策成功后按具体事件 ID 确认；失败采用持久退避和上限，重启后仍保留状态。自动规划也以事件租约、Quest 版本及原子写入约束，缺少 Provider 时保留待处理事项。真实供应商和真实 Worker 执行尚未验收；后续副作用执行仍须完成 ADR-004 所述的审批到执行回执、幂等与恢复。
