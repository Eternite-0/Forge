# ADR-004：本地 Core 信任边界与证据门槛

日期：2026-11-14。状态：已采用，实际执行器的后续接口仍需验收。

本地 HTTP 不因绑定回环地址或启用 CORS 而自动可信。Core 使用进程会话凭据，并验证来源、Host 和客户端地址；审批操作关联具体 Quest、计划修订、动作、参数摘要、范围和策略版本。未知权限默认拒绝。状态一致性检查不能替代授权。

完成路径必须在同一 SQLite 工作单元中检查当前计划的证据，再进行状态 CAS 和事件/Outbox 写入。模型陈述不是执行证据。固定 JSON 校验器在独立子进程处理限量文件，保存实际退出码、命令、工作目录与输出摘要；其 review 只覆盖 JSON 语法，文件哈希只覆盖完整性。完成条件还需要真实 Worker 运行及可信验证、逐项成功标准、必要测试和适用审批。

当前没有可信模型 Worker 执行器，也没有可验证的审批消费到外部动作运行的回执。因此这些条件无法满足时明确拒绝完成；`approval_executions` 是未来连接的持久化基础，不代表执行或投递已经实现。后续执行器必须在调用前建立持久意图、绑定和消费审批，并处理崩溃恢复和幂等；不能仅凭已消费标记宣称动作真实执行。

当前 Tauri 尚未建立安全的 Core 启动、凭据传递和原生端到端会话。CLI 和测试中的本地边界不能代替桌面集成验收。未来 Worker、Provider 与模型上下文不得获得 Core 用户会话凭据；真实执行及外部副作用必须在接入时重新审查。
