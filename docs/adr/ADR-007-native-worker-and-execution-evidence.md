# ADR-007：批准合同下的 Native Worker 与可信执行证据

状态：M5 本机冻结验收通过；适用范围见里程碑报告。

## 决策

FORGE 自有 Worker Loop 消费批准的 Quest DAG 与独立团队合同，不调用第三方 Agent 产品充当执行后端。SQLite 记录租约、checkpoint、模型消息、工具调用、预算和回执；模型调用位于写事务之外，提交时重新检查执行代次与批准范围。

工具为 Core 固定合同，运行前建立绑定计划、角色、参数摘要、资源和审批的持久意图。副作用无法与 SQLite 原子提交，因此失联后保守记录 uncertain，禁止自动重放。Mock 回执用于协议测试，不能获得真实完成信任。

完成以独立执行与产物证明为依据。当前固定 JSON 验证器只证明语法；缺失领域验证器时不能扩大完成声明。历史团队证据验证使用独立接口，允许内容完整且真实批准过的 superseded 合同；当前工具与调度仍要求 approved 合同和当前模型画像。已完成节点不得因新团队重组被重跑。

求助与换组先形成待批提案；运行中的不确定动作必须结算。有界重试/换组沿用批准计划的累计预算，不以团队替换刷新额度。全局 Worker 预算尚未覆盖 Router/planner/composer，统一 Gateway 模型调用预算在 M6 完成。

## 代价

保守不重放会把不确定效果交给用户处理；固定工具集合限制通用性，但便于审核真实执行边界。模型价格未知时只实施 token 限额，不捏造费用。合成团队与治理消融提供可复现机制验证，不能替代真实任务质量评估。
