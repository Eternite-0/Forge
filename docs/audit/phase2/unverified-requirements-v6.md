# Outstanding user requirements for final verification

This independent read-only inventory reflects retained evidence through the v6
diagnostics. The integration owner must bind any later full-suite/live results to
the final source snapshot. It is not a final verdict on a later run.

The central acceptance gap is a genuinely completed complex live task that retains
continuity through failure, review/rework, compaction/source recovery and a Core
restart. The earlier L1 pass demonstrates a narrower repair/review path. Later v6
L2/L3 still stop at budget/context/packet boundaries before the required outcome.

The paired JSON lists each request section, current evidence, required next proof
and reproducible repository evidence paths. Material remaining capabilities are:

- Actual provider context/output/rate maxima, trustworthy upstream identity and
  price remain unknown; configured ceilings and protocol success do not prove them.
- General replanning of an unfinished running DAG and hierarchical specialist
  expansion remain incomplete. Approval-bound replacement retains the same DAG.
- Learned semantic retrieval is absent; existing recall uses lexical terms and
  limited bilingual aliases with source identity checks.
- General repository patch/test/experiment execution is absent. Existing tools
  support own-artifact revision, syntax checks and a fixed numeric AST subset.
- Eight-field delivery is enforced by review criteria but is not universal across
  legacy/default compatibility contracts.
- Typed coordination exists, while exhaustive message-specific payload contracts
  remain incomplete.
- Complete online capability/quality statistics and same-budget live evaluations
  of the three research directions remain unmeasured. Fixed offline mechanism
  benchmarks are exploratory and do not establish real task-quality gains.
- Real multimodal and concurrent multi-Quest autonomous completion have not been
  established by the retained one-Quest text/code scenarios.
- Supported checkpoint/receipt recovery has local evidence; arbitrary in-flight
  effects and unknown remote outcomes remain safely fenced rather than replayed.

Fresh-context same-model review is an explicit implemented boundary; using a
different reviewer model was not an extra hard requirement. Authenticated approval
is intentional and must not be bypassed. Deferred desktop packaging is outside the
main Phase 2 acceptance requested by the user.

The inventory makes no Provider calls and does not modify source, prior reports,
credentials, run databases or historical evidence.
