## 方法与证据范围

所有案例使用同一组显式标记的合成 HTTP 投影、相同用户消息/助手正文/展开命令、真实浏览器 File API 的 1200 行源码。源码统一滚到 scrollTop=15000；设置长页统一滚到保存按钮，只观察而不提交。每次页面切换和截图前等待 220ms，覆盖现有 150ms 过渡，避免将中间宽度误判为最终布局。

固定 CSS 视口 1440×900 分别使用 DPR 1、1.25、1.5；另用 1152×720/DPR1.25 与 960×600/DPR1.5 对应相同 1440×900 物理栅格；增加 2237×984/DPR1.25 与最小 800×600/DPR1.5。每档各跑明暗两种主题。这里的 DPR 是 Chromium `deviceScaleFactor` 栅格模拟，**没有修改或验收 Windows 系统 DPI、原生窗口框架、WebView2 文件下载或系统凭据流程**。

用户原始截图为 2796×1230，Pillow 读取 PNG 元数据为空。约 125% 只根据 52px 图标栏和 288px 项目面板在截图中的比例推测，不能当作原始 DPI 已知。参考实现 `http://127.0.0.1:8890/#/settings` 则是直接读取实时 computed style；它保留项目面板再叠设置导航，与用户后来明确要求“设置隐藏工作空间面板”的结构不同，所以不拿两页绝对 x 坐标判定错误。

## 根据对照实施的校准

1. 大窗预览默认从56%调整到41%。2237CSS窗口中，调整前1058.95CSS（约1323.69物理），最终775.30CSS（约969.12物理），更接近用户截图右侧约959物理。最终预览起点1456.70CSS（约1820.88物理），截图约1837物理，保留约16px物理差距，未声称逐像素相同。
2. 中窗初始宽度仍56%（`innerWidth <= 1280`）：1152CSS下源码从41%时170.45CSS恢复291.36CSS。1000CSS以下沿用单面板，不硬挤对话与预览。
3. 树列从26%改为 `clamp(170px,28%,244px)`。参考尺寸最终217.08CSS，小于截图估计244CSS；这是为源码留出558.22CSS的适配值。中小窗口继续按已有160/220px规则处理。
4. 设置说明从tertiary约.494改为secondary .65，以恢复参考文字层级；活动摘要保持tertiary，不一起加深。

## 保留的差异与未验收

- 用户原生设置截图有分组圆角容器，参考server当前是平铺行。产品按FORGE实际功能分组，因此首行 y167.59 与server平铺 y105.59相差62CSS；不为凑坐标移除功能标题或恢复无实现的17项设置。
- 顶部壳层仍36px；用户原生截图可能还包含约8CSS的顶部内边距。原生标题栏与截图DPI未一致确认，此次未凭猜测增加8px。
- 独立项目/对话入口、Router/Worker与只读文件工作区按FORGE功能保留；不复制截图里不存在于当前产品契约的多个聊天或空开关。
- 尚未完成受控Windows 100%/125%/150%原生DPI逐屏对比及用户主观1:1确认。浏览器矩阵通过不能替代这些结果。
